# Mobile Flight Declutter (#57) Implementation Plan

> REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** A manual DCLTR toggle that hides the informational flight chrome on demand, plus nearest-few traffic labels so the windscreen never piles up — per issue #57 (owner: toggle, not auto-hide; keep top bar + stick/throttle reachable; narrow-only).

**Architecture:** Add a `decluttered` boolean to the zustand store (mirrors the existing `chromeVisible`/`immersive` pattern — the only shared channel across App/StatusBar/FlightSession/TrafficOverlay). OR `!decluttered` into each chrome element's show condition. Traffic labels get a `detailed` flag (nearest-3) in the already-sorted pure projection; non-detailed contacts render a bare marker.

**Tech Stack:** React 18 + TS · zustand · Cesium · vitest. Commands from `/home/neil/dev/adsb-game-worktrees/mongols-rich-hud/frontend`.

## Global Constraints

- Narrow-only (gate on the existing `isNarrowViewport` / `showImmersiveToggle(narrow, mode)` — desktop parity is #49, out of scope).
- DCLTR is MANUAL and orthogonal to the existing timer-based `chromeVisible` auto-hide — do NOT reuse `chromeVisible`; add a separate `decluttered` flag. `chromeVisible` fade and `decluttered` hide compose (`!decluttered && ...`).
- MUST keep reachable when decluttered: the top status bar's core row, and the touch stick/throttle/button controls. Hide only informational chrome: HUD-A/C variant button, APP button, PILOT_xxxx callsign chip, and the traffic label text boxes.
- Nearest-few = the 3 closest contacts by great-circle range get full labels (callsign/type/alt); the rest render as a bare marker (no text box). Reuse `rangeNm` from `dashboard/geoRange.ts` — do NOT add a second distance helper. The 3D Cesium chevrons already render for all contacts regardless (ContactLayer) — this only changes the DOM text overlay.
- No new dependencies. Suite green at every commit. Existing tests extended, never weakened.
- Commit per task.
